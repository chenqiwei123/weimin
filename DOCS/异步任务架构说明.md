# 异步任务调度系统架构说明

## 架构优势

### 1. 职责分离
- **ScheduledTasks（调度层）**：只负责触发定时任务，创建异步任务记录
- **AsyncTaskHandler（业务逻辑层）**：负责具体任务执行、数据库查询、业务处理
- **AsyncTaskService（协调层）**：协调任务执行、状态管理、事务处理

### 2. 避免依赖膨胀
- ❌ **旧方案**：ScheduledTasks 需要注入所有需要的 Mapper
- ✅ **新方案**：ScheduledTasks 只依赖 AsyncTaskService，每个 Handler 只注入自己需要的 Mapper

## 架构图


## 使用方式

### 新增一个任务类型

**步骤1：在 AsyncEnum 中添加任务类型**
```java
TYPE_MY_NEW_TASK("MY_NEW_TASK", "我的新任务")
```

**步骤2：创建 TaskHandler**
```java
@Component
@RequiredArgsConstructor
public class MyNewTaskHandler implements AsyncTaskHandler {
    
    // 只注入自己需要的 Mapper
    private final OrderMapper orderMapper;
    
    @Override
    public String getTaskType() {
        return AsyncEnum.TYPE_MY_NEW_TASK.getCode();
    }
    
    @Override
    public void execute(String taskParams) {
        // 在这里查询数据库、处理业务
        List<Order> orders = orderMapper.selectList(null);
        // ... 处理逻辑
    }
}
```

**步骤3：在 ScheduledTasks 中添加定时触发（可选）**
```java
@Scheduled(cron = "0 0 2 * * ?")
public void myNewTask() {
    AsyncTask task = asyncTaskService.createTask(
            "我的新任务",
            AsyncEnum.TYPE_MY_NEW_TASK.getCode(),
            ""
    );
    asyncTaskService.executeTask(task.getId());
}
```

## 核心原则

1. **单一职责**：每个类只做一件事
2. **依赖隔离**：需要什么就注入什么，不要注入不相关的依赖
3. **可扩展性**：新增任务只需创建新的 Handler，不需要修改核心框架
4. **可测试性**：每个 Handler 都可以独立单元测试

## 为什么这样设计？

| 问题 | 解决方案 |
|------|----------|
| ScheduledTasks 依赖太多 Mapper | 将查询移到 Handler |
| Handler 职责不清 | 每个 Handler 只负责一种任务 |
| 代码复用困难 | 任务处理器可单独复用 |
| 测试困难 | Handler 可以独立测试 |
